# Archived source and public adaptation

Selectively reviewed the top-level `aks-common-templates` and actual application AKS delivery templates from the September 2026 archive, then reconciled the user's three-tier explanation. The seven shared families match the earlier archive. No private Git history, estate overlays, corporate domains, credentials or certificate material was copied. Exact private source filenames and hashes remain in the local review record.

The original system separates Terraform infrastructure, independently versioned initial cluster/platform services, and application delivery. It selects environment, region and one/both clusters; common setup installs namespaces, Helm ingress, workload ServiceAccounts, reviewed manifests and optional monitoring. The app path performs ConfigMap/CSI setup, Kustomize render/apply/rollout and content verification. Current-build and selected-build promotion preserve a built release rather than rebuilding per target. Sequential cluster deployment remains the public default.

One supplied production selected-release template snapshot has commented configuration/CSI/deployment calls. This is a limit of that snapshot, not a claim that the user's established working estate was incomplete. The public implementation makes the selected successful-run receipt path executable and separately testable.

The NGINX compatibility profile retains the reviewed source chart/version, namespace/class, per-slot private frontend, replicas/autoscaling and resource settings. It tightens trust/source ranges, replaces uninstall-before-install with reviewed upgrades and is explicitly retired. Envoy/Gateway API is a deliberate migration, not a renamed NGINX installation or an assertion of annotation-level equivalence. [Migration](ingress-migration.md) records forwarded-header trust, session affinity, timeout, buffering and application-test differences. The direct-Service demo remains an optional simplified path; it is not the original full platform tier.

Targeted fixes include Entra user credentials instead of administrator kubeconfigs; explicit tenant/subscription and slot maps; isolated credentials; no source-overlay mutation; no ignored failures; public credential-free CI; approved private deployments; independent artifact checksums; scoped privileges; TLS validation; and explicit rollback/cutover. Platform packages/CRDs/values/runtime images are pinned and reviewed. Existing namespace security labels survive reruns, and CRD ownership conflicts are surfaced rather than force-overwritten.

Builds use an immutable pushed digest and the restored mandatory [HIGH/CRITICAL image-security gate](image-security.md) before emitting a promotable receipt. Successful producer/run/source bindings and scan receipt fields are checked during selected-build promotion. A digest identifies bytes; the receipt binds a reviewed source/digest pair and is not a cryptographic source attestation. Manual low-level digest/source deployment remains an explicit operator path. Mutable deployment tags, secret Docker build arguments, disabled TLS verification and automatic unreviewed rollout undo are not carried forward.

Source-specific .NET/business builds, database deployment, registry replication, commercial monitoring credentials, alternate out-of-hours approval environments and automatic maintenance are not generic defaults. They require reviewed extensions. Public examples/tests substantiate the implemented contracts, not the original company's business processes. No live Azure deployment, preview authorization enforcement or external cutover is inferred from offline tests.
